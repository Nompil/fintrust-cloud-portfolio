# Week 10 Reflection

The next migration task I would automate is the DMS validation gate. During a long Full Load plus CDC migration, an engineer repeatedly checks task state, source and target lag, table errors and validation failures. A small scheduled function can collect the same fields consistently, keep a dated record in S3 and notify the migration channel when a threshold changes. This removes repetitive console work and makes the cutover evidence easier to review. It should not approve cutover by itself. The application owner, database administrator and change manager still need to confirm smoke tests, the rollback route and the maintenance window.

For planning, I estimated five ten-minute DMS checks each weekday, two fifteen-minute DataSync checks per day, two hours of classification reconciliation and one and a half hours of reporting. That is about 11 hours each week or 154 hours during a 14 week programme. If building and testing the package takes 40 hours, the first programme saves roughly 114 engineering hours. Later waves reuse the same package, so the return improves without repeating most of the development effort. The estimate excludes incident time and should be replaced with measured run data after the first wave.
