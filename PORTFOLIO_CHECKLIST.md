Portfolio Submission Checklist

Use this checklist to make each weekly artifact presentation-ready.

Per-week checklist (apply to Weeks 1–5):
- README: short summary, how to run, key files list
- Reflection: concise `reflection.md` answering learning, decisions, struggles, and improvements
- Diagrams: ER/architecture diagrams exported to `diagrams/` (PNG or SVG)
- Code: runnable scripts or instructions; include requirements in `requirements.txt` or notes
- Exports: export important guides to `docx` or `html` for portability
- Tests: small smoke test or instructions to verify pipeline where applicable
- License/Attribution: include any third-party asset notes if used

Presentation polish:
- Ensure filenames are descriptive and stable.
- Keep commit history tidy using `COMMIT_GUIDELINES.md`.
- Remove or archive duplicates (use `archive/` folder for removed items).

Suggested final step per week:
1. Run the project checklist.
2. Commit with a focused message (e.g., `docs: add week 4 guide export`).
3. Tag a release if you plan to bundle the portfolio (optional).
