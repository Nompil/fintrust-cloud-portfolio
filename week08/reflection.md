# Week 8 Cost Reflection

The main cost decision this week was to run the monthly fraud feature job on a temporary EMR cluster instead of keeping a large analytics cluster running all month. FinTrust keeps the Primary and Core nodes on On-Demand capacity because those nodes coordinate the job and hold HDFS data. The Task fleet uses Spot capacity across more than one acceptable instance type, then the whole cluster terminates when the Spark step finishes. This lowers the cost of the extra compute used during feature generation without putting the stored dataset at the same interruption risk. The trade-off is that a reclaimed Task node can slow the job, and several interruptions could delay the features expected by the fraud team. An Instance Fleet reduces that risk by drawing capacity from different instance types, while the job can retry failed work against the Parquet source in S3. I would monitor completion time and Spot interruptions before increasing the percentage of Spot capacity. If the monthly reporting deadline became strict enough that a delay was unacceptable, I would keep more Task capacity On-Demand and accept the higher run cost.
