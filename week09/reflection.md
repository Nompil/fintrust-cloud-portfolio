# Week 9 Reflection

The Seven Rs changed the order in which I would approach the FinTrust estate. Earlier work started with an AWS service and then designed the surrounding architecture. Migration planning begins with whether the application should move at all. I would not rehost the Oracle core banking database unchanged because that would carry its licence, maintenance and operational constraints into EC2. Schema assessment followed by an Aurora PostgreSQL migration offers more long term value, provided the database team resolves incompatible procedures and validates Change Data Capture before cutover. I would not treat the tape archive as an application migration either. Its purpose is retention, so Snowball Edge and an S3 archive tier are more appropriate than running file servers in EC2. Systems that duplicate newer reporting functions or have reached end of support should be retired, not copied simply to increase a migration completion count. Mainframe workloads with hardware security or compliance dependencies may need to remain on premises until those constraints change. Rehost is useful for speed, but it is only one migration path. The framework makes each decision depend on business value, technical risk, time and the operating model after migration.
